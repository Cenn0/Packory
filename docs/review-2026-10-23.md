# Packory architecture, correctness and security review — 23 October 2026

This review identified and corrected **13 concrete defects** in upstream
resource limits, integrity admission, Skill validation/dispatch, S3 recovery,
AI backup evidence, writer admission and OCI manifest validation. The
corrections do not close the independent production-release gates.

## Architecture assessment

| Design area | Current implementation and assessment |
| --- | --- |
| Modular monolith | One ASP.NET Core application with protocol-specific endpoint classes. Appropriate for the single-writer target. The numerous modules remain in one assembly/namespace; compile-time module isolation is weaker than the proposed project layout. |
| Native protocol adapters | Eight hosted private package adapters coexist with legacy global routes. Core bytes, catalogs and authorization are shared; protocol semantics remain adapter-specific. This review found and closed a global/private OCI validation disparity. |
| Artifact model | Kind-specific ledgers and feed assets provide immutable references. The proposed general revision/distribution/asset model and globally deduplicated SHA-256 CAS are not fully implemented. Current logical keys must not be called a universal CAS. |
| Storage and visibility | Atomic filesystem publication or conditional S3 create precedes DB visibility; publication intents and recovery retain interrupted writes. These are separate transactional domains. No cross-store ACID or active-active guarantee follows. |
| Identity | Static and managed tokens, exact feed grants, namespace grants and optional OIDC JWT validation are implemented. Browser Authorization Code + PKCE/BFF, individual local accounts and complete per-action accountability remain separate work. |
| Private feeds | Native routes authenticate before querying scoped metadata; active feed kind and immutable identity are checked. Disabled drafts and private feeds have no upstream/global fallback. Existing cross-feed tests run in the local suite. |
| Skills | Staging, static review, explicit approval, revocation and digest checks form a useful distribution boundary. New admission now shares YAML parsing and compatible archive limits with MCP reads. Approval is not publisher ownership or safe execution. |
| Optional AI | Deployment-owned endpoint policy and keyring, encrypted credentials, opt-in transmission, bounded relay requests/budget and a networkless worker preserve a separate trust boundary. Model/provider detection quality and real billing remain unqualified. |
| MCP | Read-only platform MCP, inert Registry metadata and the optional future gateway remain distinct. Reviewed descriptors do not start remote services or prove publisher identity. |
| Browser | Plain JavaScript/CSS assets with a memory-only bearer field, CSP and text-node rendering. Existing mocked browser regressions cover authorization changes, hostile strings and desktop/mobile behavior. This is not BFF acceptance. |
| Operations and CI | Privacy checks, native/client/provider workflows, gated container publishing and release-evidence verification exist. Workflow source alone does not prove repository protection, a successful image build or a qualified production restore. |
| Maintainability | PostgreSQL and SQLite implement a wide shared database contract and repeat provider-specific SQL. Share bounded parsers/invariants where appropriate, retain native wire semantics, and continue provider parity tests; do not introduce microservices solely to reduce file count. |

## Trust boundaries reviewed

| Boundary | Controls examined | Remaining qualification |
| --- | --- | --- |
| Native client / browser → application | `Access`, feed lifecycle, managed grants, OIDC scopes, request limits, CSP, dashboard rendering | Complete browser BFF/CSRF/session and independent authorization audit |
| Untrusted upstream → mirror | Fixed HTTPS origins, disabled redirects, tarball-host checks, namespace reservations, checksums, metadata limits and deadlines | Legacy mirrors rely on operator/edge DNS and egress policy; they do not have the AI transport's IP-pinned connection policy |
| Uploaded archive → Skill catalog | Structural ZIP validation, YAML, staged digest, static/AI gates and human approval | Publisher signatures/ownership, scanner false positives/negatives and isolated behavior evaluation |
| Scanner output → privileged application | Separate exchange directories, bounded strict UTF-8 reports, digest/state checks, no content execution | Independent sandbox/host compromise assessment; checks are not a replacement for container/volume isolation |
| API/worker → model provider | Deployment inventory, private-CIDR policy, DNS/IP validation, numeric-address connection, no redirects/proxy/cookies, credentials only in API, cost reservations | Real provider/model compatibility, retention policy, secret rotation/DR and billing verification |
| Database ↔ blobs | Immutable bytes, provider-specific transactions, publication intents, restore fingerprints and conditional S3 operations | Actual provider failure/retention tests, coordinated restore and measured RPO/RTO |
| Source → distributed image | Pinned Actions references, non-root images, limited workflow rights, qualification and release evidence | Base/dependency reproducibility, independent SBOM/image vulnerability and signature acceptance |

## Corrected findings

Priorities describe practical impact in the documented deployment, not CVSS
scores. All rows below are corrected in this change. Their scope is the
named path; no row establishes general absence of similar defects.

| ID | Priority | Before, impact and correction | Source and executable evidence |
| --- | --- | --- | --- |
| REV-01 | P1 availability | NuGet version-index `GetAsync` buffered the complete response before checking `MaxMetadataBytes`. A 2 MiB synthetic response was fully read despite a 1 KiB limit. Stream headers first, reject oversized declared lengths and bound actual body reads. | `NuGetEndpoints.Map`; `RegistryReviewRegressionTests.NugetVersionIndexStopsReadingAtMetadataBudget` |
| REV-02 | P1 availability | `HttpClient.Timeout` stopped protecting streamed body reads after headers. A stalled origin could hold an artifact lock/request indefinitely while the downstream remained connected. A linked upstream deadline now covers header and body reads for NuGet/npm/registration; body cancellation maps to 504 and existing cached/hosted fallback policy remains. | `UpstreamDeadline`, `EnsureNuget`, `FetchMetadata`, `NugetRegistration.Fetch`, middleware; `UpstreamDeadlineIncludesBodyAfterHeaders` |
| REV-03 | P1 integrity | npm cold admission accepted a malformed/unsupported `integrity` via a matching SHA-1 fallback, while warm validation rejected it. Use the same unambiguous exact-name/version digest parser before downloading or committing the tarball. Legacy SHA-1 works only when no stronger integrity field is supplied. | `NpmEndpoints`, `NpmTarballIntegrity.ParseExpected`; `NpmColdDownloadCannotDowngradeIntegrityToShasum` |
| REV-04 | P1 scanner boundary | Static reports were read using unbounded `ReadAllText`, followed symlinks and replaced invalid UTF-8. Read no more than 1 MiB plus a detection byte, reject links/encoding errors and fail the affected revision without trusting its report. AI and static readers share `ScanExchange`. | `SkillScanCoordinator.TickAsync`, `ScanExchange`; `SkillDispatcherReviewTests.InvalidWorkerFileFailsOnlyItsRevisionAndDoesNotBlockOtherJobs` |
| REV-05 | P2 processing | Dispatch scanned only the latest 1,000 dashboard rows. Older queued work could remain permanently invisible behind completed revisions. Query pending states before pagination and cycle bounded ordinal keyset pages. | `SkillSecurityStore.PendingPage`, dispatcher cursor; `OldQueuedRevisionIsNotHiddenByThousandRecentCompletedRevisions` |
| REV-06 | P2 correctness | Import used line-prefix matching instead of YAML, accepting quoted duplicate keys and malformed structures, and storing `>-` as the description of a folded scalar. Import and MCP now use the same bounded YAML conversion and scalar contract. | `SkillFrontmatter`, `SkillEndpoints.InspectZip`; `InvalidOrAmbiguousYamlIsRejectedBeforeStaging`, `FoldedYamlDescriptionUsesItsActualText`, existing MCP typed-scalar tests |
| REV-07 | P2 portability | A file could alias an explicit or implicit directory, including case aliases; imports succeeded but MCP snapshots rejected them. Validate normalized file/parent-directory identities before staging. | `SkillEndpoints.InspectZip`; `FilesCannotAliasExplicitOrImplicitDirectories` |
| REV-08 | P2 interoperability | Import allowed 20 MiB expanded Skills but MCP refused snapshots over 16 MiB. Align MCP's total expansion ceiling with admission and bound actual decompression while reading. A 17 MiB inert asset now remains discoverable after admission. | `PackoryMcpCatalog.Get`, `SkillEndpoints.MaxUncompressedBytes`; `AdmittedSeventeenMiBSkillRemainsReadableThroughMcp` |
| REV-09 | P2 input handling | An authenticated decision with `sha256: null` caused HTTP 500. Validate the digest using a null-safe length pattern before inspecting characters. | `SkillSecurityEndpoints.ReadDecision`; `NullApprovalDigestIsBadRequest` |
| REV-10 | P1 interrupted upload | A local-only stage left before S3 acknowledgement made `PutAsync` return an immutable collision even though the remote object was absent. Serialize per key, recheck remote existence and stage the current caller's bytes afresh. Never publish abandoned bytes on that caller's behalf. | `S3BlobStore.PutAsync`; emulator-backed `S3ProviderTests.AbandonedLocalStageCannotBlockOrSubstituteNewRemoteWrite` |
| REV-11 | P1 recovery evidence | The PostgreSQL dump contained new AI tables, but backup/restore fingerprints omitted policy, jobs, budget reservations and audit. Detect the four-table optional ledger as a complete set, allowlist/fingerprint it and reject partial evidence. Historical no-AI snapshots retain their weaker profile. | `scripts/pg_s3_snapshot.py`; `test_optional_ai_tables_are_fingerprinted_as_one_complete_ledger`, snapshot regression suite |
| REV-12 | P1 writer admission | The HTTP lease check applied only to mutation verbs, although NuGet/npm GETs write caches; background scanners/AI did not check it. Gate mirror GETs and dispatcher/approval admission, cancel active AI calls and deny gateway reservations when the lease is absent. This does not fence transactions already in progress. | `Program`, both coordinators, `SkillAiGateway`; `MirrorGetsFailClosedWhenWriterLeaseIsUnavailable`, `DispatcherAndApprovalCannotWriteWithoutPostgresLease`, `AiCannotReserveBudgetOrCallProviderWithoutWriterLease` |
| REV-13 | P1 hosted OCI policy / P2 correctness | Global manifests accepted alternate `urls`, wrong descriptor sizes, invalid inline data, duplicate fields and missing required collections. All five synthetic cases returned 201. Share the private adapter's descriptor parser, require the proper shape and verify same-repository bytes/size before publication. Rejecting alternate URLs is Packory's hosted policy, not a claim that OCI forbids the optional field. | `OciDescriptors`, `OciEndpoints.ValidateDescriptors`, private adapter; `GlobalManifestRejectsUnsafeOrInconsistentDescriptors` |

## Remaining design and release work

These are existing or newly clarified qualification limits, not completed
feature promises. They remain in [Roadmap V5](roadmap-v5.md) and
[release gates](release-gates.md).

1. **Release blockers:** actual PostgreSQL/S3 provider recovery, migration/
   rollback, retention semantics, independent security assessment, complete
   supply-chain evidence and operational acceptance. No production promotion
   follows from this review.
2. **Identity:** privileged browser BFF/session/CSRF flows, finer accountability
   and publisher ownership/signatures. Retain headless scoped-token operation
   as a separate explicitly bounded deployment profile.
3. **Resource governance:** aggregate S3 materialization-cache capacity and
   eviction, OCI staging/disk quotas, HTTP concurrency/load and slow-client
   qualification. Existing size limits bound individual objects, not total
   disk, process memory or fleet-wide request cost.
4. **Egress:** legacy mirrors need deployment-enforced DNS/IP egress control
   or separately qualified connection pinning. AI transport pinning is not a
   general registry-fetch guarantee.
5. **Protocol expansion:** proxy/group feeds, private Skills/feed-aware MCP,
   broader client/version/provider matrices and full Registry lifecycle remain
   separate work. A JSON endpoint or one successful installation does not
   establish full native protocol support.
6. **Architecture:** evolve the general artifact model/CAS and compile-time
   boundaries through measured, migration-tested changes. Retain the modular
   monolith; no evidence in this review justifies active-active or microservices.
7. **Scanner/AI assurance:** independent detection/false-positive evaluation,
   actual model-provider smoke, version upgrade/recovery, secret-keyring DR,
   policy retention and explicit external transmission review.

| Claim category | Assessment |
| --- | --- |
| Works in principle | Implemented paths and listed local tests demonstrate bounded single-writer functionality and these corrections. |
| Officially supported | Only the explicitly maintained Packory client/provider matrix can define a supported profile; this review grants no upstream vendor endorsement. |
| Best practice | Keep native protocols separate, share validation invariants, use immutable references and reproduce actual client/recovery failures. |
| Security recommendation | Use the documented restricted deployment, least-privilege credentials, HTTPS and egress controls; independent production/provider gates remain open. |
