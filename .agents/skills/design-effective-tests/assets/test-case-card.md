# Testfallkarte: [fachlicher Ablauf]

| Feld | Inhalt |
| --- | --- |
| Quelle, Ziel-Commit, Umgebung | UNVERIFIED |
| Risiko / betroffener Nutzer oder Prozess | OPEN |
| Soll-Regel / Version / Eigentümer | OPEN |
| Unabhängiges Oracle mit Herkunft | OPEN |
| Vorbedingung + synthetische Fixtures | OPEN |
| Aktion (ein klarer Auslöser) | OPEN |
| Positive Erwartungen | NOT_RUN |
| Negative / Grenzwert-Erwartungen | NOT_RUN |
| Verbotene Nebenwirkungen / unabhängiger Readback | NOT_RUN |
| Fehlermodell / Gegenprobe / erwartetes Scheitern | NOT_RUN |
| Reale Integration oder klar benannter Fake | UNVERIFIED |
| Testkommando, Log/Run-ID, Commit | NOT_RUN |
| Ergebnis / Scope / verbleibende Lücken | NOT_RUN |

Ein Testfall gilt nicht wegen Dateiexistenz, grünem alten CI oder hohem Coverage-Wert als ausgeführt. Ein Negative-Control-Test muss an der erwarteten fachlichen Ursache scheitern.
